Quarkus Sonify demo

Every link sends one request to this application. The application plays one sound for the request (by HTTP method) and, a moment later, one for the response (by status code). The sound comes from the machine that runs the application, not from this page.

Click a link.

GET /boom: an endpoint that throws an exception (500).

Configured in application.properties

  • 418 plays a sound file (sounds/whistle.wav) instead of the built-in 4xx note.
  • 201 plays notes written in the configuration: notes:[tempo=160] C5/16 E5/16 G5/16 C6/8.
  • 202 plays a MIDI file (sounds/arpeggio.mid). Uncomment quarkus.sonify.soundfont to hear it, and 204, with the instrument of a soundfont.
  • OPTIONS requests are off: only their response is heard.

Custom sounds

These play a third sound, between the request and the response.

  • POST /orders: calls a bean method annotated with @PlaySound("order-placed"), which is configured to play sounds/coin.wav.
  • GET /audit: calls SoundPlayer.play("audit"). The name is not configured, so it gets a sound derived from the name.
  • POST /orders/ship: calls SoundPlayer.play("shipped"), a sound of three tones that DemoSounds defines in code.

Defined in code (DemoSounds, a SonifyCustomizer bean)

  • 409 is two flat knocks made of synthesized tones.
  • 410 is computed audio: a short downward sweep.
  • 204 is MIDI notes: a chord on a vibraphone.
  • The customizer also turns order-placed off, but the property in application.properties wins, so the coin still plays.
